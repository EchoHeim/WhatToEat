## 提醒功能失效排查（重要结论：定时触发器必须走微信 IDE）

用户反馈「提醒功能没作用」。逐层查下来，两个原因叠在一起：

**第一层：触发器根本不存在。** `tcb api scf ListTriggers` 返回 `TotalCount: 0`，函数从 2026-09-17 部署后就没配过触发器，`reminderPush` **一次都没被自动调用过**。云端的 reminders 文档（content「测试」、date 2026-10-24、time 14:30、lastPushed 空）和 `pushQuota: 8` 都正常，缺的只是触发。

**第二层：触发器创建渠道错了。** 我用 `tcb fn trigger create` 建好后手动 invoke 验证，报：
`errCode: -501001 subscribeMessage.send:fail invalid wx openapi access_token`

官方 FAQ（https://docs.cloudbase.net/faq/knowledge/missing-wxcloudapitoken-error ）与 CloudBase 社区 #1445 官解一致：
> 云调用必须由小程序端触发，不支持云控制台、Web 端、云函数调云函数、**定时触发**等方式发起（**通过微信 IDE 设置的定时触发除外**）。

即：腾讯云侧（CLI / API / 控制台）建的触发器虽然照常按时调用，但**不带小程序云调用上下文**，`cloud.openapi` 必然失败。所以那个触发器我又删掉了（留着只会固定失败、还会把 lastPushed 写脏）。

**顺带修的**：`cloudfunctions/reminderPush/index.js` 原来只比小时（`targetHour !== hour`），设 14:30 实际 14:00 就推。改成分钟窗口匹配 `inTimeWindow(time, nowMinutes, WINDOW_MINUTES=5)`，`config.json` 的 cron 改 `0 */5 * * * * *`，并支持 `{force:true}` 入参跳过窗口与 lastPushed 做链路验证。**窗口长度必须与 cron 间隔一致**。

**部署通道记录**：
- `tcb fn deploy reminderPush` 卡住 13 分钟无输出（依赖安装），SIGTERM 掉。
- 改用 CloudBase MCP `manageFunctions(action="updateFunctionCode")` + `functionRootPath`，**秒级成功**（ModTime 21:16:24）。以后部署优先走 MCP。但注意 MCP 部署**不带 config.json 的 permissions.openapi**，云调用权限仍需 IDE 上传一次。
- CloudBase MCP 工具名是 `mcp__cloudbase__manageFunctions`（ToolSearch 要用 queries，"manageFunctions" 精确名搜不到）。

**留给用户的两步（IDE 里做，我做不了）**：
1. 右键 `cloudfunctions/reminderPush` → 上传并部署（云端安装依赖）

## 续：CLI 驱动开发者工具（打通了一半）

**IDE 起不来的根因（重要，通用）**：WorkBuddy 的会话环境里有 `ELECTRON_RUN_AS_NODE=1` + `NODE_OPTIONS=<shim>`，任何 Electron 程序被这样拉起都会当 Node 解释器跑 —— 进程活着、无窗口、无日志、无子进程。之前所有"IDE 卡住"的假象都是这个。
正确姿势：
```bash
env -u ELECTRON_RUN_AS_NODE -u NODE_OPTIONS "./微信开发者工具.exe"
```
另外两点：
- 必须在**非沙箱**下启动，沙箱里 GPU 进程反复 `exit_code=-1073741819` 然后 `GPU process isn't usable. Goodbye.` 直接带走主进程；`--disable-gpu` 拦不住。
- 那个 `enableServicePort` 的 localstorage 改动**没必要**：服务端口开启后 IDE 会自己在 `Default/.ide` 里写端口号（本次 15905），CLI 自动发现。`WeappLocalData/localstorage_b72da…json` 那份备份可以不管了。
- 授权后 `cli.bat islogin` 返回 `{"login":true}`；调用时必须 `env -u NODE_OPTIONS`，否则 shim 会注入进 CLI 的 node。

**IDE CLI 实测结论**：
- `cli.bat cloud functions deploy --env <env> --names reminderPush --project <path> --remote-npm-install` → 19 秒成功，`success:true / filesCount:6 / packSize:11KB`，但：**不创建 config.json 里的触发器**（`ListTriggers` 仍 `TotalCount:0`），且**打的包在云端坏掉**：`Cannot find module './lib/reminder'`，`Duration:0 MemUsage:0`。同一份代码用 MCP `updateFunctionCode` 推上去就正常 → 问题在 IDE 侧的打包（大概率条目用了反斜杠），不在代码。
- `cli cloud functions deploy --help` 没有任何触发器参数，`cloud functions` 子命令只有 list/info/deploy/inc-deploy/download → **命令行无法上传触发器，官方也没有这个能力**。
- 所以修复顺序是：IDE CLI 上传（登记 permissions.openapi）→ 再用 MCP `updateFunctionCode` 把代码补成能跑的版本。

**-501001 不能当判据（关键认知修正）**：`tcb fn invoke` / 控制台「云端测试」/ 任何 API 手动调用**都不携带小程序云调用上下文**，必然报 `-501001 invalid wx openapi access_token`。腾讯云开发社区 issue #1445 里官方工程师明确说过这点，并给出同类签名的解法：删掉网页控制台配的定时触发器，改成 config.json 声明 + **用微信开发者工具随函数上传**。也就是说我上一轮记的「IDE 建的触发器才有上下文」方向对，但判据要换成「触发器真跑一次后的日志」。
