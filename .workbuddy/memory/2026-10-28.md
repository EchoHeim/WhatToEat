## 一次性订阅的真实规则（2026-10-28 查证，以后别再记错）
官方社区 2025 Q&A（https://developers.weixin.qq.com/community/develop/article/doc/00024292b700589d04c37999d66813 ）：
- **2.2 用户一天内点 N 次订阅，就能发 N 条通知** —— 次数**累加**，不是"一次授权终身一条"。
- **2.3 每次订阅获得的下发机会永久有效**，不按天过期。
- **2.1 勾选「总是保持以上选择，不再询问」只是不再弹窗**，用户不点按钮仍然不会增加次数；点了按钮（哪怕不弹窗）照样 +1。
- 所以"额度 > 0 就能持续推送"是**对的**，直到额度耗尽。额度记账（`pushQuota`）与微信侧次数基本一致：点一次 `requestSubscribeMessage` +1，云函数 `send` 成功 -1，`43101` 归零。
- 第 3 条文案已改为：「攒下的额度永久有效、不会过期；推送会出现在微信的「服务通知」里。」

## 切 tab 卡顿修复（15:20）

根因：4 个 tab 页的 `onShow` 都是 `await store.syncFromCloud()` 再 `refresh()`，而 `syncFromCloud` 每次都串行拉 5 个集合（`queryAll` 分页 20 条），切一次 tab 8~15 次网络往返，`await` 期间页面显示旧数据 → 表现为「卡一下再刷新」。

改法（3 处）：
1. `utils/store.js` `pullCloudData`：5 个集合改 `Promise.allSettled` 并行拉，合并写 storage 仍串行（`mergeLocalOnly` 可能要补传本地独有条目）。核心集合 dishes / meal_records 失败仍整体抛错走本地降级。
2. `utils/store.js` `syncFromCloud(options)`：加 20 秒节流窗口（`SYNC_THROTTLE_MS`），窗口内直接返回 `false`；`{force:true}` 可绕过（留给手动刷新）。返回值语义：真同步了 `true`，被节流/未开云 `false`。
3. 4 个 tab 页 `onShow` 改「先 `refresh()` 用本地缓存渲染 → 后台 `syncFromCloud().then(synced => synced && refresh())`」。首页 `onShow` 拆出 `render({keepDish})`，同步回调用 `keepDish:true` 只刷设置与签到条，不重新抽菜，避免菜品自己跳变。

未改：6 个二级页面（dish-detail / dish-form / record-form / checkins / checkin-form / reminders）仍 `await` 同步 —— 它们进入时有加载预期，且编辑页需要拿到云端最新版本，保持原样。

验证：mock 云数据库跑同步 3 次 → 首次 `true` 4 次查询 1ms、20s 内 `false` 0ms、`force` `true`；三套测试全过；`cli preview` 编译通过 154.2 KB。

副作用：跨设备改动最多延迟 20 秒才可见。

## 「最近添加 ▾」变豆腐块（15:25 修）

- `pages/dishes/dishes.wxml` 里排序控件写的是 `{{sort}} ▾`，`▾`(U+25BE) 在 Skyline 的字体栈里没有字形 → 渲染成空心小方框。
- 改成 `<view class="sort"><text>{{sort}}</text><view class="sort-caret"></view></view>`，箭头用 CSS 画：`10rpx` 方块 + `border-right/bottom: 3rpx solid #A8A49B` + `transform: rotate(45deg)`（chevron，不依赖字体，也不依赖 border 斜接）。
- **Skyline 下别用几何符号当图标**：U+25BE/25BC/2304 这类都可能缺字形，`›`(U+203A) 和 `★` 是安全的，emoji 也安全。
- 顺带确认：他截图里菜品还带 ★4.7 / 吃过 2 次，是本地 storage 里的旧 seed 缓存，清缓存或重装才会变「★ 暂无 / 吃过 0 次」。

## 记录一餐：选菜面板加搜索 + 新建入口（15:40）

原来「吃了什么」是原生 `<picker>`，只能滚动选，且不能搜索。

改法：换成页内展开面板（不用弹层，因为项目里没有 `position: fixed` 先例，Skyline 对 fixed 的支持没把握；内嵌展开是纯文档流，零风险）。
- `record-form.wxml`：`picker` → 可点击行 + `wx:if="{{dishSheetOpen}}"` 面板（搜索框 / 列表 / 底部「+ 新建菜品」）。
- `record-form.js`：`matchDishes()` 同时匹配菜名、标签、分类；面板一次最多平铺 8 道（`SHEET_PAGE_SIZE`），超出提示「还有 N 道，输入关键词缩小范围」。
- 不再用 `dishNames` / `dishIndex` / `dishChange`（原生 picker 的残留），无其它文件引用，已删。
- 无 dishId 进入时**不再默认选第一道菜**（原逻辑 `Math.max(0, findIndex)` 会默认选中，容易记错菜），改为空态提示「选择菜品」。

新建闭环：
1. `record-form.createDish()` → `/pages/dish-form/dish-form?from=record&name=<搜索词>`
2. `dish-form.onLoad` 读 `options.from`/`options.name`（`safeDecode` 兜底），预填菜名
3. 保存后若 `fromRecord && !id`，写 `getApp().globalData.pendingDishId`
4. 返回 `record-form`，`onShow`（首次用 `this.loaded` 跳过）读并清空 `pendingDishId`，自动选中新菜

`from=record` 这个标记不能省：否则从菜谱页新建的菜也会写 pendingDishId，导致下次进记录页莫名预选一道菜。

验证：三套测试全过；`cli preview` 编译通过 158.7 KB。

## 吃饭日历：限 24 个月 + 未来日期不可选 + 今天加外框（15:55）

`pages/records/*`：

### 价格 2×2 布局返工（16:15）
