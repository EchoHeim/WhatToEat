## 推送额度「无感自动补」

lodge 问：提醒推送额度怎么做到无感自动增加。结论是微信没有永久授权，唯一口子是订阅弹窗的「总是保持以上选择，不再询问」。

### 机制（查证过）
- 勾上「总是保持」后，同一模板再调 `wx.requestSubscribeMessage` **不弹窗**、直接返回 `accept`，微信侧再记一次订阅 → 额度 +1。微信官方小游戏指南把它明写成「推送多次消息的方案一」。
- 判据只有一条：`wx.getSetting({ withSubscriptions: true })` 的 `subscriptionsSetting.itemSettings`，**只包含勾过「总是保持」的模板**。空着 = 没勾过，调了就会弹窗骚扰，所以不能无脑调。
- 长期订阅走不通：只对政务/医疗/交通/金融/教育这类公共服务类目开放，「今天吃什么」拿不到。`SUBSCRIBE_MODE='longterm'` 是给别的类目留的开关。

### 改动
- `utils/subscribe.js` 重写：`refreshState()`（探状态落 `wte_sub_state_v1`）、`autoState()`（'accept'/'reject'/'off'/''）、`silentReady()`、`topUpIfNeeded()`（水位 `HIGH_WATER=60`，一小时最多 `MAX_PER_HOUR=40` 次，`toppingUp` 防连点）、`autoTopUp()`（失败不打扰，20004 记 `mainSwitch:false`）。**水位只管自动补，手动点「额度+1」不受限**（lodge 2026-10-31 定：超 60 次就不再自动加）。
- 挂载点：`pages/index/index.js` 的 `handlePick`（第一行）和 `confirmDish`；`pages/record-form/record-form.js` 的 `save`（两道校验之后、`showLoading` 之前）。**必须在 tap 回调里同步发起**，`await` 过网络就报 `can only be invoked by user TAP gesture`——这条只有真机暴露。
- **签到补挂（同日追加）**：`checkin-form.js` 的 `save`（心情校验后、`showLoading` 前）、`checkins.js` 的 `openToday` / `goForm`、`index.js` 的 `openCheckin`。签到列表点某条是「改历史签到」，**不补**。一次完整签到会补 2 次（点入口 + 提交表单），跟「就吃这个 → 记录页保存」同构。
- `onShow` 里调 `subscribe.refreshState()`（不挑手势，放这里正好）。
- `reminders` 页：`pushHint()` / `bannerSubText()` 两个纯函数按四态出文案，`reject`/`off` 时按钮变「去设置」走 `wx.openSetting({withSubscriptions:true})`；`push-guide` 从 3 条改 4 条讲清新机制。

### 自查（lodge 问「有没有引发其他 bug」）
临时冒烟脚本跑了 6 个场景，全过、运行期零错误：
- 未勾选 → 首页抽签订阅调用 **0 次**，抽签照常
- 勾选 + 额度 0 → 调用 1 次，额度 0→1
- 记录页保存 → 调用 1 次，记录照常落盘
- 没选菜就保存 → **0 次**（校验拦住就不补，不白订）
- 拒收态 → 按钮走 `openSetting`，不碰订阅接口

自查中**主动修掉**的 4 个隐患（都不是已经炸的 bug，是可能出事的写法）：
1. `writeState` 首次是 `{...null}`，补 `|| {}` 兼容老基础库转译
2. **`topUpIfNeeded` 整体包 try/catch**——它挂在抽签、保存的第一行，自己抛异常会把主流程带崩，这是最要紧的一条
3. `refreshState` 内部 try/catch，免得 `wx.getSetting` 同步抛变成 unhandled rejection
4. reminders 的 `refreshState().then(refresh)` 改成 `paintPush()`，只回填 5 个字段——异步回填比首屏慢一拍，全量 refresh 会把用户正在看的列表重渲一遍

另外 `openSetting` 的 success 回调不能改成依赖 onShow：它是原生页，关闭时不触发页面 onShow，必须靠回调自己回填。

结论：没有引发其他地方的 bug。

## 意见反馈（新增功能）

### 为什么不走微信自带的

- 类型三选一 / 正文 500 字带计数 / 最多 3 张截图 / 联系方式选填；自动带版本、机型、系统、微信版本、来源页

### 写入为什么走云函数（关键决策）
最初写的是客户端 `db.collection('feedbacks').add()`，改成云函数 `feedbackSubmit` 的三个理由：
1. 集合不存在时客户端直接报 `-502005`，而这只是部署漏了一步——云函数是管理员权限，可以自己 `db.createCollection`（`ensureCollection()` 带模块级 `collectionReady` 标记，别每次调用都撞一次）
2. 校验放服务端：长度、类型白名单、图片数量、**图片只收 `cloud://` 前缀**（外部 http 链接进来会把通知变成钓鱼入口）
3. 少一次客户端 → 云函数 → 云函数的来回

### 通知渠道：企微和飞书都支持
- 一个环境变量 `FEEDBACK_WEBHOOK` 指地址，按 host 自动认渠道：`qyapi.weixin.qq.com` → `{msgtype:'markdown'}`，`open.feishu.cn` → `{msg_type:'post'}` 富文本；认不出用 `FEEDBACK_WEBHOOK_TYPE=wecom|feishu` 强制指定，不认就不发（只入库）
- **飞书签名**：配 `FEEDBACK_WEBHOOK_SECRET` 才带 `timestamp` + `sign`。算法是 **`HMAC-SHA256(key = "${timestamp}\n${secret}", data = "")`**——key 和 data 是反的，按常规写法签会一直报 19021
- **成功判据不只看 HTTP 状态码**：企微 `errcode` / 飞书 `code`（旧版 `StatusCode`）都要查，地址填错时照样返回 200
- 飞书 post 的 `content` 是二维数组，空行要塞一个空格（纯空串的 text 节点会被丢掉，段落粘一起）
- **截图只能发链接，不能内嵌**：飞书/企微的图片消息要 `image_key`，而 `image_key` 得用应用凭证（app_id/app_secret）调 `im/v1/images` 上传，群机器人没有应用身份。`resolveImageUrls()` 用 `cloud.getTempFileURL` 把 fileID 换成临时链接，飞书用 `{tag:'a'}` 超链接、企微用 `[第 N 张](url)`；**链接默认只有 2 小时**，过期点开 403；取链接失败要降级成「N 张（临时链接没取到，去控制台看）」，别让推送跟着失败
- 想做内嵌图片，得上飞书自建应用：`tenant_access_token`（有效期 2 小时要缓存）+ `im/v1/images` + `im/v1/messages`，且要把应用机器人拉进群——比 webhook 重一档，lodge 还没决定要不要

### 云函数运行时升级（已完成 2/3）
**核心事实（纠正之前的说法）**：

- **运行时不可原地修改**，腾讯云 SCF `UpdateFunctionConfiguration` 文档原文：`Runtime：函数运行环境，创建时指定，目前不支持修改。` → 只能删了重建。
- **MCP v2.36.2 白名单只到 `Nodejs20.19`**，平台文档虽支持 22.21/24.11/26.x，但 MCP 枚举没跟上（传 24.11 直接报「不支持的运行时」）。要更高版本得走控制台或 CLI。

已做：`syncBatch`、`feedbackSubmit` 都从 16.13/18.15 → **Nodejs20.19**（删了重建，FunctionId 变了但函数名不变，客户端按名字调用无感）。

- 冒烟验证只覆盖了模块加载 + `cloud.init`（invoke 不带 OPENID，走不到 `notify` 分支）。真实推送要 lodge 提交一条反馈才算验到。

### 隐私声明运行时核验：自动化路线走不通（别再试）
想用官方 `miniprogram-automator` 在模拟器里逐个调 4 个隐私接口、靠 `errno 112` 反推后台勾了哪几项。结果三层全堵：
1. **后台勾选项读不到**：唯一查询接口 `cgi-bin/component/getprivacysetting` 只给「第三方平台代开发」用（要 authorizer_access_token），且**不支持云调用**。自己的小程序没有只读入口。
2. **`cli auto` 不给开端口**：已有 IDE 实例在跑时，`cli auto` 只会复用窗口，`--auto-port 9420` 不监听（`Get-NetTCPConnection` 查不到）。必须先 `cli.bat quit` 彻底退干净再 `cli auto`。
3. **沙箱拦 `reg.exe`/`wsl.exe`**：CLI 起 IDE 时报 `PROGRAM BLOCKED BY SECURITY POLICY`，IDE 起不来。`Start-Process` 直接拉 exe 能起来（会打印整段启动日志），但**工具会话一结束进程就被回收**，窗口留不住。
- `automator.connect()` 在端口没监听时**也会打印「已连接」**，之后所有 `evaluate`/`systemInfo` 全超时——别把「connected」当成功。
- 结论：这台机器上核验隐私声明只能靠**人点**（反馈页选图 / 改头像 / 改昵称 / 导出复制文本 / 导入选文件）。
- 清掉了 `.workbuddy/tools/auto-check/node_modules`，留着 `probe.js`（改天 IDE 真能开自动化再用）。

### 隐私声明运行时核验结果（lodge 在 Console 跑通）
Console 输出：`指引名称: 《食来运转机小程序隐私保护指引》 待授权: false` → **指引已配置且已生效**。
- `needAuthorization: false` 的含义：当前微信号此前已点过同意，后续不再弹窗。**判声明是否缺失只能看 `errno 112`**（112 是「没声明」，与是否已授权无关）。测新用户弹窗得清授权数据或换号。
- `wx.setClipboardData` 那条**没有任何输出**：lodge 贴的命令只带了 `fail` 回调（我文档里给的是 success+fail 都带）。fail 没触发 ⇒ 无 112 ⇒ **剪切板已声明**。

### Console 索引建议（已落地）
截图里 `快速创建索引链接 ... collection=dishes` 是云开发按实际查询推荐复合索引。查证：四个集合都只有 `_openid_1` / `updatedAt` / `id` / `_id_` 单字段索引。
