## 两处「跨月就红」的脆弱测试（顺手修）

今天真实日期从 10-31 跨到 11-01，跑全量时 `pages` / `regression` 各红一条 —— 不是这次改动引起的，是测试自己钉死了 2026-10：

- `pages.test.js`「当周有纪念日时标题带上纪念日」：靠 `a3`（10-31 万圣节纪念日）落在「本周剩余」区间。跨天后 10-31 变成昨天，`weekAnniversaries` 的 `offset < 0` 直接跳过。修法两条：① 加 `a4` 钉在**今天**（`2020-${today.slice(5)}`）保证任何一天都在区间内；② 标题断言从「必须等于 `本周节日 · 纪念日`」放宽成「含『纪念日』」—— 标题有三支（无纪念日/只有纪念日/两者都有），只认第三支等于要求当天正好是节日。
- `regression.test.js`「有记录的日子不给空态卡」：前面「跳回本月」那段把 `page.year/month` 改成了今天所在月，之后选 10-12 就被判「不在当前月」，找不到记录。修法：选日子前先 `page.year = 2026 / page.month = 10 / page.refresh()` 切回去。
- **教训**：测试里凡是「固定年月 + 依赖今天」的组合，跨月/跨年必红。要么把被测日期钉到今天，要么断言放宽到不含具体日期。

## 「额度+1」按钮撑满整行（`.push-btn` 收窄）

lodge 截图指出按钮宽得离谱。根因不是 flex 写错，是**小程序 `button` 组件自带 `width: 100%`**，而 `app.wxss` 只重置了 `button { margin: 0 }` 和 `button::after { border: 0 }`，没管宽度。在 `.status-push` 这条 flex 行里，它一路撑开，把左边文案压成 4 行。

- 修法：`.push-btn` 补 `width: auto`（特异性 (0,1,0) 压过内置 `button` 的 (0,0,1)）+ `max-width: 200rpx` 兜底 + `box-sizing: border-box`。
- 实测内容宽：`额度+1` 4 字 × 24rpx + 左右 padding 22rpx ≈ 140rpx；`去设置` 3 字 ≈ 116rpx，都在 200rpx 内。
- **同类隐患**：其它用 `<button class="ghost-btn">` 的地方（如空态卡「清空条件」）同样是 100% 宽，只是背景浅、看不出来。真要收窄得逐个加 width。
- 编译 354.7 KB，测试全绿。

## 首页筛选不再即时换菜

lodge：点「清空」时主页菜品不该变，只有点「开始随机选」才换（还带动画）。

  - `pick()` 默认不带 `celebrate`，空态补抽不会放彩带。
- 筛选生效后的可见反馈只剩右上角 `filter-badge` 数字 —— 原来那个「从 N 道候选中选出」已经删了。
- `regression.test.js` 加 6 条断言守这个行为：有菜时清空/选条件都不换菜、不触发抽签，空态清空才补抽。
