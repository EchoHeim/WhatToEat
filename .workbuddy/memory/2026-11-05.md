- 只支持 `theme`（transparent/white/black）和 `width` 两个属性；自包含交互，不抛事件、不传业务参数（作者标识/头像墙/人数/跳转链接全后台下发）。
- 稿位金额 ¥1/¥2/¥3/¥5/¥6 + 其它，跳转到绑定的贴图页完成。

**平台条件**：**仅个人主体小程序可开通**（企业主体反而开不了），**平台抽成 0**。开通只在手机微信里做：`微信开发者助手` 小程序 → 我的业务 → 小程序 → 赞赏 → 开通 → 绑定本人贴图号或公众号 → 发一篇讲这个小程序的贴图 → 回到赞赏页「加入赞赏组件」。文档未要求认证/备案（虚拟支付才要求）。

## 首页骰子按钮「emoji 压到文字上」（部分设备）

现象：`🎲 开始随机选 8` 三块在部分机型上贴在一起，骰子压到「开」字上；同一份代码在另一些机型正常。

**两个原因叠在一起**：
1. **emoji 字形宽度跟设备字体走**。Apple Color Emoji / Noto / 三星那套（advance width 1.17em）各不相同，Skyline 的文本测量按字体 metrics 算，彩色字形实际绘制可能超出 advance box。
2. **`gap` 在 Skyline 老版本不支持**（社区实测 1.3.3 不支持、1.4.1 才修；还有 `gap + var()` 的组合 bug）。原样式 `.dice-inner{gap:12rpx}` 在低版本等于没有间距。

12rpx 本来就窄，两边一挤就贴上了。

**修法**：不让渲染引擎算间距。给 emoji 一个固定宽度的盒子 + 显式 margin：

```css
.dice{flex:none;width:48rpx;margin-right:12rpx;font-size:34rpx;line-height:1.2;text-align:center}
.dice-inner{...} /* 去掉 gap */
.dice-label{flex:none;white-space:nowrap}
```

48rpx 比 34rpx 字号宽出 14rpx，专门吃字形溢出，再加 12rpx margin 兜底。`.recent-emoji`（最近吃过那排 chip）同病同治，`gap:10rpx` 换成 `margin-right:10rpx`。

**项目里还有一批 `emoji + 文字` 靠父级 `gap` 排队**（records 的 search-emoji / festival-line / meal-emoji / hit-emoji、report 的 top-emoji、dishes 的 dish-emoji、record-form 的 sheet-emoji）。它们间隙是 14~18rpx 且 emoji 字号与正文接近，暂未复现，但同一个坑。以后再看到哪处贴边，照上面这套改，别回去用 gap。

本次改动随 `Ver0.0.11` 一起发。

## 赞赏组件点不动 → 挪出 scroll-view（2026-11-06，Ver0.0.12）

0.0.11 上线后用户反馈点「喜欢开发者」没任何反应。**根因是位置**：组件原来放在 `pages/profile/profile.wxml` 的 `<scroll-view scroll-y type="list">` 里，Skyline 下 list 容器会吃掉子节点的点击——按钮画得出来，点不动。`reward` 又自带跳转、不抛任何事件，坏了连日志都没有，只能靠外部排查。

**改法**：移到 `</scroll-view>` 之后、`<template is="app-tabbar">` 之前，绝对定位吸底。

```css
page { ...; position: relative; }   /* absolute 的定位基准 */
.reward-dock { position: absolute; left: 0; right: 0;
  bottom: calc(150rpx + env(safe-area-inset-bottom));  /* tabBar 顶上沿 142（122 高 + 20 间距）再上 8 */
  z-index: 50;                                          /* tabBar 是 100，不能压 */
  padding: 12rpx 32rpx 14rpx; background: #F7F4ED; }    /* 与页面同色：滚动内容穿过不脏，未开通时也看不出来 */
.version-bar { padding-bottom: calc(320rpx + env(safe-area-inset-bottom)); }  /* 让开 reward 140 + 26 + tabBar 142 */
```

`theme` 从 `transparent` 改成 `white`：底是米色，白底才看得出卡片边界。

**教训**：Skyline 下凡是「自己绘制、自带手势」的组件（reward、自定义 tabbar）都别放进 `type="list"` 的 scroll-view。这个项目已经栽过两次。

**上传卡住**：`cli quit` 重启 IDE 会把登录会话一起清掉，之后 `upload` 报 `需要重新登录 (code 10)`，`cli login` 又被安全策略拦（IDE 登录流程要调 `reg.exe`）。下次改代码前**别 quit**，直接复用已登录的 IDE。

## 推荐菜谱库（200 道）+ 按人群分类（Ver0.0.12 未升号）

### 数据：`utils/recipes.js`

- **纯静态常量，不进 storage、不参与云同步**。跟着版本走，用户不能改；落本地要占配额，还得处理「新版加菜、老用户本地没有」的迁移。
- `CROWDS` 八类：`toddler` 幼儿 / `child` 儿童 / `teen` 青少年 / `middle` 中年 / `elder` 老年人 / `pregnant` 孕妇 / `fitness` 健身减脂 / `chronic` 三高调理。数组顺序即界面顺序。每条带 `group`（`age` 前五个 / `need` 后三个），**界面按它分两排**，不加 `group` 的新人群不会出现在筛选里。
- **人群筛选布局**：第一排「全部 + 年龄段」六个，第二排「特殊需求」三个。不写分组标题文字，靠换行区分。chip 用 padding 20 / 字号 24 / 间距 10（比分类那排紧）——按原来的 26/25/14 算，第一排要 746rpx，内容区只有 686rpx，会把「老年人」挤到第三行。
- **人群筛选是单选退出、多选进入**：`data.crowds` 是数组，「全部」不是一个选项，而是「数组为空」。点「全部」= 清空，互斥天然成立不用维护；点具体人群 = toggle。多选之间取**并集**（`crowds.some(key => item.crowd.includes(key))`）。
- wxml 里不做数组查找：`crowdRows(selected)` 把两排结构和 active 标记一起算好（跟首页 `filterChoices` 一个路子）。
- 人群说明只在**选中一个**时显示，多选时几条拼起来太长会挤掉列表。
- 每条只有 `crowd` 和 `why` 是新字段。**`crowd` 绝不能混进 `tags`**：`report.js` 的口味偏好统计按 tags 算，混进去会把「孕妇」统计成一种口味。
- 默认值在 `normalize()` 里补：`mealTypes: ['午餐','晚餐']`、`eatTypes: ['自己做']`、`tags: []`。原始数据只写「跟默认不一样」的，两百多条才不至于每条都重复一堆字段。
- **共 220 道**（后 20 道是幼儿辅食，r201–r220，一律无盐无糖、泥糊羹为主）。
- 最终覆盖（含重叠）：幼儿 20 / 儿童 47 / 青少年 85 / 孕妇 20 / 中年 91 / 老年人 55 / 减脂 33 / 三高 24；跨人群 101 条。
- **青少年标签收窄规则**（用脚本批量跑，不是手改）：只保留「tags 含高蛋白」「tags 含聚餐」「category 属主食类（米饭/面食/快餐/韩餐/日料/火锅/烧烤）」三种，其余摘掉；摘完为空时兜底给 `middle`。原始是 121 条，太宽（家常菜它都能吃，筛出来跟「全部」没区别），收窄后 85。

- 脚本改完务必 `node --check` + 全量 12 套回归；`store.test.js` 里那条「人群标签跟着复制」原来钉死了 `'elder'`，标签体系一改就红，后来改成只断言 `includes('elder')`。

### 两个坑已从根上修掉（同日）

**① bootstrap 残留读缓存** —— 双层：
- `migrateTagRename()` 自己直接读 `wx.getStorageSync(KEYS.dishes)`，不经过 `getDishes()`，从源头不产生缓存
- `bootstrap()` 末尾统一 `resetReadCache()` 兜底：以后谁在启动流程里读数据，都不会把「启动中途的快照」留给后续

## 「我的」页：推送未开启的提示（2026-11-07）

「提醒事项」卡片下面挂一行红字，`pushTip` 为空串时整行不渲染。判据直接用 `subscribe.autoState()` 的四态：

| autoState | 文案 |
|---|---|
| `accept` | 不显示 |
| `off` | 微信通知总开关关着，提醒不会响 |
| `reject` | 你拒过推送授权，到点不会提醒 |
| `''` | 还没勾选「总是保持」，推送额度用完就停 |

- `''` 和 reject/off 要分开写：`''` 只是没勾「总是保持」，一次性授权的额度还在，说「不会响」是错的
- 状态只能异步问微信：`onShow` 里 `subscribe.refreshState().then(() => this.refresh())`，查询失败退回上次缓存，不影响页面
- 点这行 → `wx.openSetting({ withSubscriptions: true })`。reject / off 微信不给接口直接改，只能引导用户自己拨回来
- 这一行放在 `.settings` 卡**外面**，不要塞进卡片里：`.setting-row:last-child { border: 0 }` 会被它顶掉，卡片底下多出一条分割线
