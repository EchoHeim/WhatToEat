# 今天吃什么

一个帮你决定「这一顿吃什么」的微信小程序。

收录自己的菜品，按餐次、口味、预算圈定范围，摇一次骰子定下来；吃完记一餐、写一句当天心情。日历把每一餐和心情放进同一张日卡，往回翻能看见自己这大半年是怎么吃的。另有一个独立的日期提醒模块，支持公历 / 农历与循环规则，可选接入微信订阅消息做真正的到点推送。

技术形态是原生小程序 + Skyline 渲染 + 微信云开发，无 npm 依赖、无构建步骤，导入微信开发者工具即可编译运行。

## 功能

### 随机推荐（首页）

- 四个维度可叠加筛选：餐次（早餐 / 午餐 / 晚餐 / 夜宵）、分类（13 类）、用餐方式（自己做 / 外卖 / 堂食）、预算档（经济 / 普通 / 丰盛 / 豪华，对应 10 元以下 / 10–30 / 30–120 / 120 元以上）
- 点「帮我选一个」播放约 1.2 秒滚动动画（12 步 × 100ms）后在候选里落定；候选超过一道时保证不与上一次相同
- 自动避开最近 N 天吃过的菜（不过滤 / 3 / 7 / 14 / 30 天，默认 7 天），也可整体允许重复；单道菜可以单独标记为不参与随机
- 结果卡显示「3 天前吃过」与平均分，确认后点「就吃这个」直接进记录页，餐次已预填
- 候选为空时提示放宽条件，并给出一键清空

### 节日（`utils/festival.js`）

- 三类共 **38 个**：中国传统节日 14 个（腊八 / 小年 / 除夕 / 春节 / 元宵 / 龙抬头 / 上巳 / 端午 / 七夕 / 中元 / 中秋 / 重阳 + 清明 / 冬至两个节气节日）、国际节日与国际日 18 个、中国法定纪念日 6 个
- 农历节日**每年现算**（走 `utils/lunar.js`），不写死某一年的公历日期；闰月不重复过节；除夕按「腊月最后一天」算，腊月廿九那年也对
- 清明与冬至是节气，用寿星通用公式 `int(Y×0.2422 + C) - int((Y-1)/4)` 算，误差最多一天
- 母亲节 / 父亲节 / 感恩节是「某月第 N 个星期几」，按当月第几个算
- `weekFestivals()` 返回本周剩余节日（最多 3 条），按日期升序

### 菜品库

- 搜索（菜名 / 标签）、按分类过滤、四种排序：最近添加、名称、评分、吃过次数
- 新建、编辑、详情、删除。字段：名称（20 字）、Emoji 图标（内置图标库，默认平铺 24 个，可展开）、分类、标签、适用餐次、用餐方式、预算档、备注（200 字）
- 评分与吃过次数不由用户填写，统一从饮食记录聚合重算；改一餐会同时回算被换下和被换上的两道菜

### 记录与吃饭日历

- 一餐一条记录：餐次、菜品、日期、**具体时间（时:分，默认取当前时刻、可改）**、1–5 分（0.5 步进）、四档状态（吃得很好 / 还不错 / 一般般 / 不太行）、200 字随手记
- 日卡里的餐按时间先后排；老记录没有 `time` 时用 `createdAt` 兜底，列表里不会留空
- 日历页一天一张卡：心情图标 + 随笔 + 当天各餐。有心情的日期在日历上显示心情图标，只有餐的显示当天第一道菜的图标
- 点日历格子只看那一天，再点「查看整月」回到整月；日历最多往回翻 24 个月
- 「＋ 一餐」可补记历史日期，不能选未来；点某一餐是编辑（菜品 / 餐次 / 日期 / 评分 / 状态 / 备注都可改），长按是删除
- 顶部汇总当前范围的「N 餐 · M 天心情」
- 日历下面挂「本周节日」：本周还剩的节日才出现（周一算一周之始，已经过去的不提醒），一行一个，带倒计时、分类标签和「吃点：XX」；看当月且没挑某一天时才挂
- **在日历上点某一天**，那一块改成显示那天的节日与纪念日（标题「X 月 X 日这天」），那天什么都没有就不显示
- **有节日的那天，日历数字是亮蓝色**；**自己加的纪念日那天是亮紫色**。同一天两者都有时紫色赢；今天 / 选中态的颜色压过它们
- 当周存在的自定义纪念日也会列进同一块，标题自动变成「本周节日 · 纪念日」

### 心情与签到

- 只记心情，不掺饮食（和「记一餐」是两条独立数据线）；**16 个心情，签到页 4×4 宫格**选择（`images/moods/*.png`：羞愧/厌恶/自豪/嘴馋/嫉妒/愤怒/高兴/孤独/焦虑/满足/迷茫/难受/疲惫/平静/期待/惬意）；200 字随笔；一天一条，再保存即覆盖；可补历史，不能选未来
- 老心情（开心/兴奋/平淡/低落/忙乱/瞌睡）在 `utils/checkin.js` 的 `LEGACY_KEYS` 里映射到新的一套（高兴/期待/平静/难受/焦虑/迷茫），历史签到不会变成同一个表情
- 页面顶部每进一次随机显示一句古诗词（诗经 / 楚辞 / 唐诗 / 宋词共 100 句，单句不超过 20 字），取自 `utils/quotes.js`，不会连着两次重复
- 连续签到天数：今天已填则从今天往前数，今天还没填则从昨天往前数，当天补填后自动接上
- 心情页汇总本月心情分布（按次数倒序）、最近 14 天心情条带（缺失那天显示为灰点）与历史心情列表
- 首页顶部有一条签到提示，未签到时点它直接进写心情页

### 日期提醒

完整语义见下文「日期提醒：能力与含义」，这里只列形态。

- 入口在「我的 → 日期提醒」，列表按 纪念日 / 今天 / 未来 7 天 / 更远 / 已关闭或已结束 分组
- 支持公历与农历（含闰月，1900–2100）、不重复 / 每天 / 每月 / 每年四种循环、当天 / 提前 1 天 / 提前 3 天三种提前节点
- **同一张表单还能建「纪念日」**：纪念日每年都有（公历按同月日、农历按农历同月日）
- 纪念日**默认不推送**，只在日历上把那天标成紫色；打开「到期提醒」开关后，可以像普通提醒一样选**当天 / 提前 1 天 / 提前 3 天（可多选同时提醒）**与提醒时间，会照常推送并计入当日角标；停用整条则不推
- 云函数扫描时按 `kind` + `notify` 判断：没开提醒的纪念日一律跳过，开了的跟普通提醒走同一套触发计算
- 卡片开关可临时停用，轻点编辑、长按删除；「我的」页会显示条数与当日提醒角标
- 应用内提醒开箱可用；微信服务通知需要自己申请模板并部署云函数

### 个人资料与统计

- 收录菜品数、本月记录数、平均评分、「目前最喜欢」（评分最高者，并列时取吃过次数多的）
- 昵称与头像走 `chooseAvatar` / 昵称填写能力，头像上传云存储，换设备自动恢复
- 三个偏好项：默认餐次、最近天数、是否允许重复

### 跨设备同步

- 同一微信账号在不同手机上读同一份云端数据；不同账号通过 `_openid` 与集合权限隔离
- 写操作本地先落盘，云端失败只提示不阻断；某个集合缺失时只让对应功能退回本地缓存，补齐后下次启动自动补传

## 技术结构

### 选型

| 层       | 选型                                   | 说明                                                                    |

| 本地存储 | `wx.setStorageSync`                    | 五个键（`wte_dishes_v1` 等），首屏只读本地                              |

| 云端文件 | 云存储                                 | 头像；同样仅创建者可读写                                                |
| 云端计算 | 云函数 `reminderPush`                  | Node + `wx-server-sdk`，5 分钟定时触发器                                |
| 消息     | 订阅消息                               | 前端 `wx.requestSubscribeMessage`，云端 `openapi.subscribeMessage.send` |
| 测试     | Node 直跑                              | 三个纯函数测试脚本，不依赖开发者工具                                    |

### 数据流

`utils/store.js` 是唯一数据入口，页面不直接调 `wx.cloud`：

```
页面 → store（本地 storage 先写）→ 云数据库（异步补同步）
                                ↘ 失败：保留本地 + 可读错误提示
```

所有页面统一「先渲染本地缓存 → 后台 `syncFromCloud()` → 同步成功再 refresh」，不把网络请求挡在首屏之前。

### 纯函数引擎

- `utils/lunar.js` 农历换算，覆盖 1900–2100，含 2020–2035 全量公历↔农历往返校验
- `utils/reminder.js` 提醒触发计算：给定一条提醒与日期区间，算出全部事件日与触发日
- `utils/checkin.js` 连续天数、14 天条带、心情分布与概览模型
- `utils/festival.js` 节日库：农历 / 节气 / 公历 / 浮动节日、自定义纪念日命中，与「本周还剩哪些日子」
- `utils/reminder.js` 里还有 `isAnniversary` / `anniversaryNotify` / `anniversaryHit`：纪念日判定、要不要推送、落在哪一天（云函数用前两个决定推不推）

四者都不依赖小程序 API，可以直接在 Node 里回归。`festival.js` 只在客户端用，不用同步到云函数。`lunar.js` 与 `reminder.js` 在云函数里各有一份副本（`cloudfunctions/reminderPush/lib/`），**改完必须同步复制**，否则小程序端和云端对触发日的判断会不一致。

## 日期提醒：能力与含义

这个模块和「记一餐」是两条独立的数据线：提醒只负责在某个日子提醒你，不写饮食记录。理解它的关键是把「事件日」和「触发日」分开。

### 一条提醒包含什么

| 字段     | 取值                         | 含义                             |
| -------- | ---------------------------- | -------------------------------- |
| 提醒内容 | 40 字以内                    | 推送时截断到 20 字（模板限制）   |
| 日历     | 公历 / 农历                  | 农历含闰月，范围 1900–2100       |
| 日期     | 公历日期或农历月日           | 叫「基准日」，循环规则以它为锚   |
| 循环     | 不重复 / 每天 / 每月 / 每年  | 见下一节                         |
| 提醒时间 | 精确到分钟，默认 09:00       | 决定推送落在哪个时间窗口         |
| 提前节点 | 当天 / 提前 1 天 / 提前 3 天 | 可多选，至少保留一个             |
| 启用     | 开 / 关                      | 关掉即进「已关闭」，不再参与计算 |

### 四种循环的准确语义

| 循环   | 事件日怎么定                                       | 边界处理                                                                                                    |
| ------ | -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 不重复 | 只有基准日一天                                     | 过期后归入「已结束」，不再触发                                                                              |
| 每天   | 从基准日（含当天）起每天一次                       | 提前节点没有意义，表单会隐藏并强制按当天算                                                                  |
| 每月   | 公历取每月同一「日」；农历取每个农历月的同一「日」 | 基准日为 31 日时，遇到只有 30 天的月份收敛到月末；农历遇 29 天的月份同理                                    |
| 每年   | 公历取每年同月同日；农历取每年同一农历月日         | 2 月 29 日在平年收敛到 2 月 28 日；基准是闰月而当年没有该闰月时，回退到同名常规月（「闰二月」按「二月」算） |

### 「提前 N 天」到底改变了什么

提前节点不是「多提醒一次」，而是把一个事件日拆成多个触发日。

举例：事件日为 4 月 10 日，提前节点同时勾了当天、提前 1 天、提前 3 天，会产生 4 月 7 日、4 月 9 日、4 月 10 日三个触发日，每个触发日各算一次、各推一条。列表里「今天」分组是按**触发日**算的，不是按事件日算——所以 4 月 7 日那天打开小程序，这条提醒会出现在「今天」。

推送文案也据此生成：触发日当天是「就是今天」，其余是「还有 N 天」。

### 提醒时间与 5 分钟窗口

定时触发器每 5 分钟跑一轮（cron `0 */5 * * * * *`），云函数只处理「提醒时间落在刚刚过去那个 5 分钟窗口内」的记录：14:30 的提醒会在 14:30–14:34 那一轮命中，14:35 那一轮已经超窗，因此既不重复也不补推。

这条规则带来两个可感知的后果：

- 提醒时间可以精确到分钟，但实际送达有 0–5 分钟延迟
- 关掉小程序期间错过的触发日不会补推，也不会在列表里留一条「逾期」；循环提醒直接跳到下一个触发日

窗口长度（云函数里的 `WINDOW_MINUTES`）必须与 cron 间隔一致。把 cron 改回每小时一次却留着 5 分钟窗口，整点之后的提醒会全部漏掉。

### 去重与推送额度

- 每条提醒记录 `lastPushed`，当天推过就跳过，同一事件日最多一条推送
- 云函数下发前检查用户 `pushQuota > 0`
- 微信「一次性订阅」的规则是**授权一次只能推一条**：用户每完成一次授权 `pushQuota` 加 1，推送成功或收到 `43101`（未订阅 / 额度用尽）后尽力减 1 或清零，额度为 0 时不发消息，用户需重新点「开启」授权
- 所以每收到一条服务通知，就欠一次授权。这是平台规则，不是实现上的偷懒
- `config.js` 的 `SUBSCRIBE_MODE` 控制是否校验额度：`'once'`（默认）按上面记账；`'longterm'` 是长期订阅，授权一次可长期下发、跳过额度校验，但仅政务民生 / 医疗 / 交通 / 金融 / 教育等线下公共服务类目可申请。工具类、电商类、内容类在公共模板库里只能选一次性订阅

### 应用内提醒与微信推送的边界

- **应用内提醒**：打开小程序就能看到今天该提醒的事，零配置，不依赖云函数
- **微信推送**：需要模板 + 云函数 + 触发器 + 用户授权四件事全部就位。小程序不支持后台本地推送，没有模板时就只有应用内提醒

### 部署推送链路

1. 微信公众平台申请模板（服务类目要先配好，公共模板库按类目展示），记下模板 ID 与关键词列表
2. 模板 ID 填两处且保持一致：`utils/subscribe.js` 与 `cloudfunctions/reminderPush/lib/config.js`；关键词映射改后者的 `TEMPLATE_FIELDS`
3. 开发者工具里上传部署云函数，再右键 `config.json` → **上传触发器**

两个容易踩的坑：

- **模板关键词一个都不能漏**。缺哪个微信就报 `47003 argument invalid! data.XXX.value is empty`，而且一次只报一个，容易误判成只差一个字段。多余 key 会被忽略，排查时可以直接填超集
- **触发器只能用微信开发者工具上传**。`tcb` CLI、腾讯云控制台、CloudBase 等方式建的触发器虽然同样按时调用，但缺少小程序云调用上下文，`cloud.openapi` 一律返回 `-501001 invalid wx openapi access_token`

当前用的是一套 5 关键词的「日程提醒」类模板，映射已按真机通知反推确定，落在 `lib/config.js` 的注释里。它是日历类模板，套在用餐提醒上「地点」槽只能用来放日期——换模板后需要重新对各行的实际位置。

## 本地运行

1. 安装并打开[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)
2. 导入本项目根目录
3. 确认登录微信号拥有该小程序的开发权限
4. 确认云环境、五个集合与云存储权限已就位
5. 点「编译」，再用「预览」做实机测试

项目不依赖 npm，无需安装依赖或构建。只有部署提醒推送云函数时才需要 `wx-server-sdk`，由开发者工具的「云端安装依赖」自动完成。
