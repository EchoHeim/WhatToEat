# 今天吃什么

一个帮助用户快速决定“这一顿吃什么”的微信小程序。项目包含个人菜品库、条件随机、饮食记录、月历和基础统计，并使用微信云开发实现同一微信账号跨设备同步。

## 功能

- 按餐次、分类、用餐方式和价格范围筛选菜品
- 约 1.3 秒的随机选择动画，结束后展示推荐结果
- 自动过滤最近 N 天吃过的菜品
- 菜品搜索、分类、排序、添加、编辑、详情和删除
- 记录早餐、午餐、晚餐和夜宵
- 支持 0.5 分步进评分、饮食状态和备注
- 吃饭日历一天一张卡：当天心情、随笔和当天各餐放在同一块，有心情的日期在日历上显示心情图标
- 菜品数量、本月记录、平均评分和偏好统计
- 昵称和头像保存至云端，跨设备恢复
- 云数据库同步，本地缓存作为网络异常时的兜底
- 日期提醒：支持公历 / 农历、按日 / 月 / 年循环、提前 1 天 / 3 天提醒、微信订阅消息推送
- 每日签到：一天一条，选心情图标 + 写随笔，统计连续签到天数、本月心情分布与最近 14 天条带；饮食不在这里重复记录，直接取当天的饮食记录

## 技术结构

- 微信原生小程序：JavaScript、WXML、WXSS
- Skyline 渲染模式
- 微信云开发文档型数据库
- 微信云函数与定时触发器（提醒推送）
- 微信云存储
- `wx.setStorageSync` 本地缓存

## 日期提醒

入口位于「我的 → 日期提醒」。

### 支持能力

| 维度 | 取值 |
| --- | --- |
| 日历 | 公历、农历（含闰月，1900-2100） |
| 循环 | 不重复、每天、每月、每年 |
| 提前提醒 | 当天、提前 1 天、提前 3 天（可多选） |
| 提醒时间 | 精确到分钟，用于微信推送 |

循环语义：

- **不重复**：只在指定日期按提前设置提醒一次，过期后列表归入「已结束」。
- **每天**：从起始日期开始每天提醒，此时提前设置无意义，表单会自动隐藏。
- **每月**：公历按每月同一日，31 日在只有 30 天的月份自动收敛到月末；农历按每个农历月的同一天，遇到只有 29 天的月份自动收敛到月末。
- **每年**：公历按每年同月同日；农历按每年同一农历月日。基准月为闰月时，当年没有该闰月会自动回退到常规月（例如「闰二月」在无闰月的年份按「二月」计算）。

列表按「今天 / 未来 7 天 / 更远 / 已关闭或已结束」分组，轻点编辑，长按删除，卡片右侧开关可临时停用。

### 微信推送（可选，需自行部署）

小程序无法在后台本地推送，「到点提醒」必须通过微信订阅消息实现。应用内提醒无需任何配置即可使用；如需收到微信服务通知，按以下步骤启用：

1. **前置条件**：小程序需在「设置 → 基本设置 → 服务类目」中配置好服务类目，公共模板库按类目展示模板，未配置类目可能搜不到可用模板。
2. **申请模板**：微信公众平台（<https://mp.weixin.qq.com>）→ 功能 → 订阅消息 → 公共模板库 → 搜索关键词（如「提醒」）→ 选用。**选完先记下模板详情里的关键词列表**（形如 `thing1` / `thing2` / `time25` / `short_thing19`），第 5 步要照着它填。
3. **复制模板 ID**：提交后在「我的模板」中查看。注意不同小程序选用同一个模板生成的模板 ID 也不同，必须复制自己后台的这一串。
4. **填入模板 ID**（两处必须一致）
   - 小程序端：`utils/subscribe.js` 的 `TEMPLATE_ID`
   - 云函数端：`cloudfunctions/reminderPush/lib/config.js` 的 `TEMPLATE_ID`
5. **对齐字段映射**：`TEMPLATE_FIELDS` 的 key 必须与模板关键词一一对应，value 从 `content` / `eventDate` / `time` / `note` / `category` 里选。
   - 模板里的关键词**一个都不能漏**，漏掉哪个就会报 `47003 ... data.XXX.value is empty`，而且微信一次只报一个，容易误以为只有一个字段。
   - 当前模板（`HcqoSxy...`）是一个 **5 关键词的「日程提醒」模板**，映射已按真机收到的通知反推确定：

     | 模板关键词 | 通知里的位置 | 取值来源 |
     |---|---|---|
     | `thing5` | 日程标题 | `content` 提醒内容 |
     | `thing2` | 提醒内容 | `note` 就是今天 / 还有 N 天 |
     | `time25` | 时间 | `time` `HH:mm` |
     | `thing10` | 地点 | `eventDate` 2026年10月24日 |
     | `short_thing19` | 日程类别 | `category` 固定「用餐提醒」 |

   - 这是日历类模板，套在用餐提醒上「地点」槽只能拿来放日期。**换模板后必须重新对各行的实际位置**：先把候选字段填满保住投递，再看一眼真机通知里哪一行显示了什么，据此收窄——多余 key 会被微信忽略，所以填超集不会报错，只会显示错位。
   - 各字段取值长度与格式已按微信规范处理：`content` 截断到 20 字，`eventDate` 输出「2026年10月24日」（`date` 类字段只接受年月日写法），`time` 输出 `HH:mm`。
6. **部署云函数**：在微信开发者工具中右键 `cloudfunctions/reminderPush` → 上传并部署（云端安装依赖）。`config.json` 已声明 `subscribeMessage.send` 权限和每 5 分钟一轮的定时器。

   > 首次部署若报「请在编辑器云函数根目录（cloudfunctionRoot）选择一个云环境」：说明开发者工具还没绑定云环境。先**完全关闭并重新打开开发者工具**（`cloudfunctionRoot` 是后加的配置，工具不会重载），重启后右键 `cloudfunctions` 目录 → **选择当前环境** → 选中 `cloud1-d7gua1dxyb865738c`，再执行上传部署。

7. **上传触发器**（关键，漏了这一步提醒永远不会自动跑）：右键 `cloudfunctions/reminderPush/config.json` → **上传触发器**。

   > ⚠️ **触发器必须由微信开发者工具上传**。用 `tcb` CLI、腾讯云控制台或其他 API 创建的定时触发器，虽然是同一个 cron、也能按时调用云函数，但**不带小程序云调用上下文**，云函数里的 `cloud.openapi.subscribeMessage.send` 会固定报错：
   >
   > ```
   > errCode: -501001  subscribeMessage.send:fail invalid wx openapi access_token
   > ```
   >
   > 官方口径是「云调用必须从小程序端触发，不支持云控制台、Web 端、定时触发等方式发起（**通过微信 IDE 设置的定时触发除外**）」。同理，函数也建议用开发者工具上传，`config.json` 里的 `permissions.openapi` 才随之上报生效。

8. **用户授权**：在提醒列表页点「开启」完成一次订阅授权，或在保存提醒时打开「同时发送微信提醒」。

> 调试小技巧：云函数支持 `{ "force": true }` 入参，会忽略时间窗口和 `lastPushed`，按今天直接推一次，用来验证模板/授权/额度链路是否通。注意它会真的消耗一次推送额度。

### 推送额度说明

微信「一次性订阅」的规则是**授权一次只能推送一条**：

- 用户每完成一次授权，`user_settings.pushQuota` 加 1。
- 云函数推送成功或收到 `43101`（未订阅 / 额度用尽）后，尽力将该值减 1 或清零。
- 额度为 0 时云函数不会下发消息，用户需要重新点「开启」授权。

因此每条提醒推送后都需要重新授权一次。

**订阅类型切换**：`cloudfunctions/reminderPush/lib/config.js` 里的 `SUBSCRIBE_MODE` 控制是否校验额度。

- `'once'`（默认）— 一次性订阅，按上面的额度逻辑记账。工具类、电商类、内容类小程序在公共模板库里只能选用这一种。
- `'longterm'` — 长期订阅，授权一次可长期下发，云函数跳过额度校验。仅政务民生、医疗、交通、金融、教育等线下公共服务类目可申请，需提交行业资质，普通类目申请会被驳回。

也就是说：除非你的小程序类目在上述开放范围内，否则保持默认值即可。

### 云函数执行逻辑

每 5 分钟触发一轮（cron `0 */5 * * * * *`），逐个检查 `reminders` 集合中 `enabled: true` 的记录：

1. 当前北京时间落在提醒时间之后的那个 5 分钟窗口内（14:30 的提醒在 14:30–14:34 命中，14:35 那轮已超窗，不会重复）；
2. 当天确实是触发日（事件日按提前天数回退）；
3. 当天尚未推送过（`lastPushed` 去重）；
4. 用户 `user_settings.pushQuota > 0`。

全部满足才下发订阅消息，并写入 `lastPushed` 标记。窗口长度由 `WINDOW_MINUTES` 控制，必须与触发器 cron 间隔保持一致——把 cron 改回每小时整点却留着 5 分钟窗口，会让整点之后的提醒全部漏掉。

## 饮食与心情（记录页）

饮食记录和每日心情在**「记录」页**合并成一套：一天一张卡，卡里放当天的心情、随笔和当天各餐。原先签到里还有一个手写的「吃了什么」输入框，和饮食记录是两份数据，改了一边对不上另一边，现在已去掉——饮食只有一个来源（`meal_records`），心情只负责心情。

### 页面结构

```
吃饭日历        有心情的日期显示心情图标，否则显示当天第一道菜的图标
今天还是空白    今天没餐也没心情时出现，点一下直接写心情
这个月 / 这一天  N 餐 · M 天心情
日卡            🥳 10 月 24 日 · 周六 · 今天   [＋ 一餐]
                心情 兴奋 · 2 餐
                "今天加班到八点，火锅救了我"
                午餐 🍅 番茄炒蛋 ★4.5
                晚餐 🍲 火锅 ★5
```

- 点日期或心情图标 → `checkin-form` 写 / 改当天心情
- 点「＋ 一餐」→ `record-form` 且带上那一天（可以补记历史日期）
- 长按某一餐 → 删除
- 点日历格子 → 只看那一天，再点「查看整月」回到整月

### 心情表单

`checkin-form` 现在只管两件事：**心情（9 个图标）+ 随笔（200 字）**。饮食部分退化成一行只读汇总（「番茄炒蛋、番茄炒蛋 · 2 餐」），点它直接跳去记一餐，返回时自动刷新，不会覆盖已选的心情和没保存的随笔。

| 维度 | 取值 |
| --- | --- |
| 心情 | 9 个内置图标：😄 开心 / 🥳 兴奋 / 😋 满足 / 😌 惬意 / 😐 平淡 / 😪 疲惫 / 😕 低落 / 🤯 忙乱 / 🤤 嘴馋 |
| 随笔 | 200 字以内，显示在日卡里 |
| 饮食 | 只读，来自当天 `meal_records`，不在签到里重复写 |
| 日期 | 默认今天，允许补签历史日期，不能选未来 |

规则说明：

- 一天只保留一条心情记录，同一天再次保存即为覆盖。
- 「连续签到」：今天已填则从今天往前数；今天还没填则从昨天往前数，当天补填后会自动接上。
- 本月心情分布按出现次数倒序，统计口径只取当月；最近 14 天条带缺失的那天显示为灰点。

心情写在 `daily_checkins` 集合，核心字段为 `date`（`YYYY-MM-DD`，一天一条）、`moodKey` 与 `mood`（图标副本，便于展示兜底）、`note`。`diet` 是旧版本留下的手写文本，页面不再写入，编辑老记录时原样保留不清空，列表展示优先用当天饮食记录汇总、没有时才回退到它。连续天数与心情统计都是纯函数（`utils/checkin.js`），可以直接在 Node 里回归。

## 数据同步

首次启用云端时，程序会检查当前微信用户的 `user_settings`：

- 云端尚未初始化：将当前设备的本地菜品、记录、提醒和设置迁移到云端。
- 云端已经初始化：从云端拉取该用户的数据并刷新本地缓存；拉取时会把「只在本机、从没同步成功」的条目先补传上去（按 id 判重，心情记录按日期去重），避免集合缺失期间存的数据被空云端覆盖。
- 云端请求失败：继续使用本地缓存，写入失败时向用户提示。

同一个微信账号在不同手机上打开同一 AppID 的小程序时，会读取相同的云端数据。不同微信账号通过 `_openid` 和集合权限隔离。

## 用户头像与昵称

受微信隐私规则限制，小程序不能静默读取真实微信头像、昵称或微信号：

- 用户首次点击头像后，通过 `chooseAvatar` 选择头像并上传云存储。
- 用户首次点击昵称后，通过昵称填写能力选择或输入昵称。
- 保存完成后会自动显示，并在其他设备上恢复。

## 维护提示

`utils/lunar.js` 与 `utils/reminder.js` 是纯函数模块，同时在云函数中被复用。**修改后必须复制到 `cloudfunctions/reminderPush/lib/` 覆盖旧副本**，否则小程序与云端对触发日的判断会不一致。

云函数的定时触发器**只能通过微信开发者工具上传**（右键 `config.json` → 上传触发器）。用 `tcb` CLI、腾讯云控制台、CloudBase MCP 等方式创建的触发器虽然在 SCF 侧存在、也会按时调用，但缺少小程序云调用上下文，`cloud.openapi` 一律返回 `-501001 invalid wx openapi access_token`。排查时先用 `tcb api scf ListTriggers` 确认触发器是否存在，再确认它是怎么来的。

## 当前限制

- 菜品图片目前使用 Emoji 代表图标，尚未提供菜品照片上传。
- 每天的心情一天一条，不支持一天多次；心情图标为内置 9 个，暂不支持自定义。
- 记录页目前不支持编辑已有的一餐（只能长按删除后重记），也没有跨月搜索。
- 分类和标签使用内置选项，尚未提供独立的分类/标签管理页。
- 数据同步采用前端直连云数据库，依赖集合和云存储权限正确配置。
- 提醒推送依赖订阅消息模板，未申请模板时只能在打开小程序时看到应用内提醒。
- 农历换算支持 1900-2100 年，超出范围会回退到公历日期。

## 故障排查

保存提醒后如果提示「已保存到本机」，说明本地缓存写入成功、但云端写入失败，数据不会丢，修好配置后重新保存一次即可同步。提醒列表页顶部也会出现红色横幅直接写明原因。

代码里已把云开发的错误码翻译成可操作的提示（`utils/store.js` 的 `describeCloudError`），常见对应关系：

| 错误码 | 含义 | 处理 |
| --- | --- | --- |
| `-502005` | 数据库集合不存在 | 云开发控制台 → 数据库 → 新建提示里点名的那个集合，权限「仅创建者可读写」 |
| `-502003` | 权限不足 | 把集合权限改为「仅创建者可读写」，或检查安全规则是否拦截写入 |
| `-502002` | 数据库拒绝请求 | 同上，通常是集合权限被设为「仅管理端可读写」 |
| `-501000` | 云开发环境未初始化 | 确认 `app.js` 中 `wx.cloud.init` 的 `env` 与云开发控制台一致 |
| `-501001` | 云调用拿不到 access_token | 检查定时触发器是不是用 `tcb` CLI / 腾讯云控制台建的——必须改成微信开发者工具里右键 `config.json` → 上传触发器。另外确认云环境与小程序属于同一主体且已绑定 |
| `-501001` | 云环境不存在 | 核对 `app.js` 中的 `env`，环境可能已被删除或换了地域 |

提示里的集合名取自实际写入失败的集合（由 `upsertCloud` / `removeCloud` 挂在 `error.collectionName` 上），所以签到保存失败时会提示 `daily_checkins` 而不是其他集合。

其他常见问题：

- **上传云函数报「请在编辑器云函数根目录（cloudfunctionRoot）选择一个云环境」**：`cloudfunctionRoot` 是后加的配置，开发者工具不会热重载。完全关闭并重新打开工具，再右键 `cloudfunctions` 目录选择云环境。
- **`dishes` / `meal_records` / `reminders` / `daily_checkins` 任一集合缺失**：功能是各自独立容错的，缺失的集合只会让对应功能退回本地缓存，不影响其他功能；集合补建后，本地那些没同步成功的数据会在下次启动同步时自动补传上去（`pullCloudData` 里的 `mergeLocalOnly`）。
- **用 CLI 一次性建好全部集合并设权限**（需本机装好并登录 `tcb`）：

  ```bash
  ENV=你的环境ID
  for c in dishes meal_records user_settings reminders daily_checkins; do
    tcb db nosql execute -e $ENV --command "[{\"TableName\":\"$c\",\"CommandType\":\"COMMAND\",\"Command\":\"{\\\"create\\\":\\\"$c\\\"}\"}]"
    tcb api tcb ModifyDatabaseACL --body "{\"EnvId\":\"$ENV\",\"CollectionName\":\"$c\",\"AclTag\":\"PRIVATE\"}"
  done
  ```

  `AclTag: PRIVATE` 就是控制台里的「仅创建者可读写」。
