# 用户隐私保护指引：声明清单与可粘贴文本

代码侧能做的只有两件事：**对准要声明哪几项**、**把文案写好**。
最后一步（在小程序管理后台提交）必须你本人操作——Agent 登不了公众平台，这一步没法代劳。

---

## 一、后台路径与生效时间

```
小程序管理后台 → 设置 → 服务内容声明 → 用户隐私保护指引 → 去完善
```

**新增的声明约 5 分钟后才生效**（官方原文）。提交完立刻进模拟器测试，会看到「接口未声明」的旧错误，那是没等够，不是没勾对。

---

## 二、本项目需要声明的 4 项

对照官方《小程序用户隐私保护指引内容介绍》里的接口映射表，一个个核过调用点：

| # | 声明项 | 触发它的代码 | 建议填写用途 |
| --- | --- | --- | --- |
| 1 | 收集你的昵称、头像 | `pages/profile/profile.wxml:9` 的 `<button open-type="chooseAvatar">`<br>`pages/profile/profile.wxml:11` 的 `<input type="nickname">` | 用于在小程序内展示你的头像和昵称 |
| 2 | 收集你选中的照片或视频信息 | `pages/feedback/feedback.js:77` 的 `wx.chooseMedia`（最多 3 张，仅图片） | 用于随意见反馈提交问题截图，帮助定位问题 |
| 3 | 收集你选中的文件 | `pages/profile/profile.js:109` 的 `wx.chooseMessageFile`（仅 `.json`） | 用于从聊天记录中选择备份文件，恢复你之前导出的饮食记录 |
| 4 | 读取你的剪切板 | `pages/profile/profile.js:80`、`98` 的 `wx.setClipboardData` | 用于把备份内容复制到剪贴板，方便你保存到别处 |

> 第 4 项容易漏。官方表格把 `wx.setClipboardData`（**写入**剪贴板）也归在「读取你的剪切板」这一类里，看着别扭，但分类就是这样定的，不勾会直接 `errno 112`。

### 后台弹窗里的勾选框怎么对

「开发者处理的信息」点「请选择」会弹出一个叫「使用用户信息类型」的复选框列表，**它上面的文案和指引正文的措辞不一样**，容易对不上号。按这张表勾：

| 弹窗里的勾选框 | 对应指引正文 | 本项目 |
| --- | --- | --- |
| `用户信息（微信昵称、头像等）` | 收集你的昵称、头像 | ✅ 勾 |
| `选中的照片或视频...` | 收集你选中的照片或视频信息 | ✅ 勾 |
| `选中的文件` | 收集你选中的文件 | ✅ 勾 |
| `剪切板` | 读取你的剪切板 | ✅ 勾 ← **最容易漏这项** |

其余**一律不勾**。弹窗里那个 `设备信息` 是历史遗留选项，官方现行映射表（2026-07-28 版）里已经没有「设备信息」这一分类，`wx.getDeviceInfo` 也不在清单内；勾了等于多声明一项你并不采集的信息，只会给审核添话题。

## 三、确认过不需要声明的（别多勾）

多勾不算错，但会让用户在授权弹窗里看到与你功能无关的说明，反而像在乱要权限。

| 接口 | 位置 | 为什么不用声明 |
| --- | --- | --- |
| `wx.getDeviceInfo`、`wx.getSystemInfoSync` | `pages/feedback/feedback.js:52,56`、`components/navigation-bar/navigation-bar.js:63,66` | 官方隐私接口映射表里**没有「设备信息」这一类**，这两个接口不在清单内 |
| `wx.getFileSystemManager` | `utils/store.js:643,662` | 读写本机备份文件，不在清单内 |
| `wx.shareFileMessage` | `pages/profile/profile.js:85` | 转发文件到聊天，不在清单内 |
| `wx.cloud.uploadFile`、`wx.cloud.callFunction` | 多处 | 云开发自有能力，不在清单内 |
| `wx.requestSubscribeMessage` | `utils/subscribe.js` | 订阅消息授权，不属于用户隐私接口 |

**一个容易勾错的**：反馈页 `wx.chooseMedia` 的 `sourceType` 写的是 `['album', 'camera']`，看起来像要用摄像头。但官方把 `wx.chooseMedia` 整体归入「收集你选中的照片或视频信息」，「访问你的摄像头」那一类只对应 `scope.camera`、`<camera>`、`wx.createVKSession`、`<live-pusher>` 这些。**所以不需要额外勾摄像头。**

**但设备信息建议在「补充说明」里主动提一句**，这是诚实原则，也省得审核来问：

```text
本小程序在提交意见反馈时会附带机型与系统版本信息，仅用于定位问题，不用于识别个人身份，也不会与第三方共享。
```

（补充文档只收 `.txt` 纯文本，不超过 100KB。不填也能过，填了更稳。）

## 五、提交后的自检

### 先看这 5 条（后台页面上能直接看到）

| # | 核对项 | 通过标准 |
| --- | --- | --- |
| 1 | 「使用用户信息类型」勾选框 | **4 个**：用户信息、选中的照片或视频、选中的文件、**剪切板**。多一个少一个都不对 |
| 2 | 「开发者处理的信息」正文 | 有 **4 句**「开发者收集/读取你的……」，且用途和代码里实际用途一致 |
| 3 | 「开发者对信息的存储」 | 填了具体期限，**不能空着** |
| 4 | 「联系方式」 | 邮箱已填（用户行使查阅/删除权的入口） |
| 5 | 页面顶部状态 | **审核通过**，不是「审核中」/「已驳回」 |

**「平台会自动生成必填项」这句话要打个折**：官方原文是「微信会根据小程序版本隐私接口调用情况展示必填项」。这里的「小程序版本」指**线上版本**——如果线上版本里还没调用过某些接口（比如一直只在开发版里跑），后台就不会自动列出，全靠手动勾。所以第 1 条必须自己数，别指望它自动填。

只勾复选框而正文没写对应句子，属于「声明与内容不一致」，审核会驳回。两边必须对齐。

### 再按报错码判断

**先确认贴对地方**：下面这段是 JS，要贴进**微信开发者工具的调试器 Console**（模拟器下方「调试器」面板 → Console 标签；没有面板就点菜单栏「视图 → 调试器」），**不是** 系统终端 / Git Bash——bash 会把 `$`、`{}` 当语法报 `ParserError`。

```js
// 第一步：不弹任何界面，先看指引配没配上、剪贴板声明了没有
wx.getPrivacySetting({ success: r => console.log('指引名称: ' + r.privacyContractName + ' / 待授权: ' + r.needAuthorization), fail: e => console.log(e) })
wx.setClipboardData({ data: 'probe', success: () => console.log('剪贴板: 已声明'), fail: e => console.log('剪贴板: ' + e.errno + ' ' + e.errMsg) })
```

```js
// 第二步：会弹选择器，看完取消就行
wx.chooseMedia({ count: 1, mediaType: ['image'], sourceType: ['album'], success: () => console.log('照片视频: 已声明'), fail: e => console.log('照片视频: ' + e.errno + ' ' + e.errMsg) })
wx.chooseMessageFile({ count: 1, type: 'file', extension: ['json'], success: () => console.log('选文件: 已声明'), fail: e => console.log('选文件: ' + e.errno + ' ' + e.errMsg) })
```

- `指引名称` 若是《…小程序隐私保护指引》，说明后台指引已配置并生效；**空串 = 没配上**
- 任一项打出 `112`，就是该项没勾
- 若报 `can only be invoked by user TAP gesture`，说明模拟器把手势校验放在隐私检查之前，改用真实入口点：反馈页「添加图片」、我的页「导入备份」

| 现象 | 含义 | 怎么办 |
| --- | --- | --- |
| `errno 112`，`api scope is not declared in the privacy agreement` | 该项没声明 | 回后台补勾，**等 5 分钟**再测 |
| `errno 103` | 用户拒绝了「与授权弹窗耦合」样式的官方弹窗 | 正常行为，引导用户重试 |
| `errno 104` | 用户拒绝了「直接弹窗」样式 | 同上，**10 秒内**再调用不会重复弹窗 |
| `fail appid privacy api banned` | 提审时勾了「未采集隐私」，或根本没声明 | 后台重新声明后重新提审 |

调试时清掉已同意状态：开发者工具 → 清缓存 → **清除授权数据**；或把小程序从「微信下拉 → 最近使用」里删掉。

## 六、代码侧**不用**改的地方（省得白折腾）

1. **`app.json` 不用加 `__usePrivacyCheck__`**。
   官方原文：2023-10-17 之后不论是否配置，隐私相关功能都会启用。这个开关已经没意义了。

2. **不用实现 `wx.onNeedPrivacyAuthorization`**。
   没实现时，微信会自动接管、弹出**官方隐私弹窗**，用户同意后接口照常执行。只有想自定义弹窗样式才需要写。

3. **但有一个隐藏行为要知道**：官方原文明确写了，`<input type="nickname">` 在用户同意隐私协议之前**不会触发** `onNeedPrivacyAuthorization`，而是**静默降级成普通 `<input type="text">`**。
   对本项目无影响——`profile` 页的昵称本来就是用户自己打的（`bindblur="nicknameChange"`），不依赖微信回填。但要知道这个现象，别以为是 bug。

## 七、还剩一件只能你确认的事

用到的四个接口都已列入上表。但**平台会扫描代码包自动生成必填项**，那张清单以你打开后台时看到的为准。

如果后台自动勾上了我上表之外的项（比如「访问你的摄像头」），说明平台从代码里扫到了我没识别出的调用——**按后台的勾，然后回来告诉我，我去代码里找对应位置核对**。
