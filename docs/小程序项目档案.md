## 改动记录

### 2026-11-07 · 无障碍（aria）补齐

| 项 | 内容 |
|---|---|
| 范围 | 13 个页面 WXML + `styles/tabbar.wxml` + `pages/records/records.js` |
| 方式 | 91 处精确文本替换，每条要求命中恰好 1 次（补丁脚本内置断言，任一不合即整条不写入） |
| 结果 | `aria-label` 由 12 个增至 **88 个**；非原生语义的可点击元素 **78 个，缺标签 0 个** |

**为什么状态写进 `aria-label` 而不是依赖 `aria-selected`**：选中态一律拼进文本（如「我的菜谱，已选中」），这样即使 `aria-selected` 在 Skyline 下不生效，读屏仍能把状态念出来。`aria-role="tab"` 只承担角色语义，读不出也不丢信息。

**日历格 label 增强**（`records.js`）：原来只有「11 月 7 日，2 餐」，而节日 / 纪念日 / 提醒在界面上全靠**颜色和红点**表达，读屏完全无法感知。现在拼成：

```
11 月 7 日，今天，2 餐
11 月 15 日，纪念日
11 月 20 日，有提醒
11 月 26 日，节日
```

实现上把 3 个判断从对象字面量提成局部变量，供 `labelBits` 与对象字段共用，**调用次数不变、无副作用**。

**验证方式**：

| 校验 | 方法 | 结果 |
|---|---|---|
| 只加属性、没动内容 | 把新文件的 `aria-*` 全删后与备份逐字比对 | 14 个 wxml **全部一致**，差异 0 |
| 标签结构 | 抠掉 `{{ }}` 后解析标签流，检查开闭配平 | 结构错误 0 |
| 属性合法性 | 同一标签内不重复 `aria-*`、`aria-role` 在白名单、`{{ }}` 配平 | 违规 0 |
| 字段引用 | 抠出 `aria-label` 里的顶层变量，与页面 data + 运行时 setData 字段对账 | 88 个 label，未命中 0 |
| 日历 label 实际输出 | 种「今天+2 餐 / 纪念日 / 提醒 / 节日」四类数据跑 `buildMonthView` | 四类全部正确念出 |
| 回归 | 12 套测试 | 全绿 |

**改了一条测试断言**：`regression.test.js` 原有 3 条断言把 `bindtap` 写死在 `class` 之后（`/class="checkin-bar" bindtap="openCheckin"/`），插入 `aria-*` 就失效。已改为 `[^>]*` 同标签内匹配——**仍然要求 `bindtap` 落在同一个起始标签上**，只是不再对属性顺序敏感。这是断言过敏，不是代码问题。

## 待办与已知问题

### 待办

1. **颜色无设计 token**（唯一剩余体检项）：389 处十六进制硬编码 + 15 处 `rgba()`，其中 `#E85D3F` 出现 41 次、`#F6F2EA` 19 次、`#292824` 19 次。WXSS 支持 CSS 变量，但 **Skyline 下的支持度需以官方文档核实**。建议先在 `profile` 页试点（颜色种类最少，出问题一眼能看出），真机验过再铺开。
2. **`prettier --check` 仍有 45 个文件不通过**（`utils/store.js`、`utils/reminder.js`、各页 `.json`、`sitemap.json` 等）。这是历史遗留，与 2026-11-07 两次改动无关——上一轮只格式化了改动涉及的文件。要统一需单独一次「只跑 prettier」的提交，避免把格式 diff 和功能 diff 混在一起。

### 已知问题 / 刻意保留的设计

- **`aria-role="tab"` 的支持度需真机核实**：用在 4 个 tabbar 项与菜谱页两个分段按钮上。若读屏不报「标签页」，改成 `aria-role="button"` 即可——状态已经在 `aria-label` 文本里，不丢信息。
- **`switch-wrap` 没有 aria**：`pages/reminders` 里 `<view class="switch-wrap" catchtap="noop">` 是纯事件拦截层（阻止冒泡到父级的编辑/删除），不是功能入口；里面的 `switch` 已有 `aria-label`。给它加 aria 反而多念一个空节点。
- **`custom-tab-bar/index.wxml` 只有 35 字节**：`<view class="placeholder"></view>`，是框架要求的空壳。改它的 aria 对真机无效果。
- **无障碍不影响审核**：小程序审核不强制 `aria-*`（与 Web 的 WCAG 不同），这一项纯粹是体验投入。
- **`reminderPush` 保持 Nodejs16.13**：运行时不可改，删了重建会连带失去只能在 IDE 图形上传的触发器。
- **`getSystemInfoSync` 是有意保留的兼容回退**，不是遗留代码。
- **不做分包**：总体积 767K，远低于 2MB 限制。
- **共享读缓存返回数组本身**：就地 `.sort()` 前必须 `.slice()`，`dishes.js` 已有注释示范。
- **`utils/{reminder,lunar,notify}.js` ↔ `cloudfunctions/reminderPush/lib/`** 是手工副本，改前端必须复制。
- **`.no-border` 特异性靠层叠顺序**：`record-form.wxss` 里是 `.no-border { border: 0 }`（0,1,0），依赖它排在 `.field` 之后。`.field` 已在 `app.wxss`，页面样式天然更靠后，顺序仍成立；另外三个表单页用的是 `.field.no-border`（0,2,0），跟顺序无关。
